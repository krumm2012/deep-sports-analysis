## 3. 需要修正或明确保留的问题

### A. 直接影响截图中教练结论的问题

1. **源码中的历史建议与网页嵌入数据需要分别追溯。** `profiles_report.py` 中的 `COACH_NOTES` 是历史 Claude 建议的静态文字，不是每次运行重新生成。该源码脚注明确说这段建议先于手机相机校正，并列出 Peter 的部分数值变动及两项失效判断；实时网页和本地网页快照没有这段脚注，不能把源码模板当作当前网页的逐字副本。截图中 Richard 的髋转角 43°、肘伸直程度、发球触球高度等涉及当前手机规则中被标记为不可靠或不可测的指标，但不能由此认定 Richard 所有已发表数值都未校正。新 Codex 复刻应注明具体数据来源和版本，排除不可测指标；不得直接把历史段落改名为 Codex 输出。详细数值核对见下节。

2. **二维投影角不是实测三维关节旋转。** `technique.turn` 通过肩线/髋线的有符号横向投影宽度与该次动作内最大宽度之比取 arccos，推算转动。这依赖机位、身体姿态以及动作确实经过可作为参照的最大展开状态。视角不正、肩髋遮挡和关键点噪声会影响角度。应称“二维投影转动代理量”，不能把 43°、156°等当作三维动捕精度的测量。

3. **手机校正是经验归一化，不是相机标定。** `profiles.foreshortening` 用身高与表观躯干长度的比值，迭代调整图像纵向缩放，使手机与职业组的统计比例接近。这个假设可能混入真实身材比例、屈膝、躯干倾斜和球场尺度误差；它不能恢复朝向镜头的深度。原文也承认手机与电视机位不重叠，不能直接外推电视镜头回归。复刻应同时保存校正前/后值和敏感性结果。

4. **职业差异不是训练干预的因果证据。** 热力图描述的是风格差异，没有展示“改变该指标后球速、稳定性或比赛成绩改善”的实验。原文只选 11 名双手反拍职业球员，也主动限制了对单反的外推。因此 Codex 应把练习当作待验证假设，不应把职业中位数写成所有人的最佳动作目标，更不能推出伤病风险。

### B. 测量与统计复现的问题

5. **时间对齐依赖未充分评估的击球检测。** 所有动作以击球预测帧为零点。原文 Table 5 明示镜头切分与击球检测未评分；但击球偏移会同时移动触球特征和 +0.3 秒收拍取样。F³Set 原论文单独评估时间定位，本项目不能用上游论文分数替代当前片段的验证。至少应人工复核触球帧，并报告不同时间容差下的 precision/recall/F1、正反手混淆和左右手分组表现。

6. **统一 60Hz 网格不增加真实帧率。** 当前 `atp_hardcourt` 配置 `hz=60`，同时 `fine=False`、`fine_measures=False`；下载输入的 50/60fps 常规视频被减为 25/30fps，随后关键点插值到分析网格。不能以 1/60 秒网格间隔声称 60fps 的真实动作观测精度。必须保存原生 fps、分析 fps、时间插值方法、F³ED stride 和触球帧误差。

7. **热力图的 z 是效应尺度，不是显著性。** 代码是“本人的逐拍中位数减其他职业球员中位数的中位数”，除以各职业球员逐拍方差的平均再开方。它不是 p 值，也不是以职业球员中位数之间的标准差做分母。`spread` 的文档字符串写“围绕中位数”，实际 `np.nanvar` 使用均值中心；精确复现以实现公式为准。颜色在 ±1.5 饱和，红蓝只表示更大/更小。

8. **显著性检验与热力图走不同路径。** `profiles.compare` 先取 player×match 的均值，再做 Welch 检验与每个球员内部的 Holm 校正；单元最低只有 2 拍，该球员至少需要 2 场。这样比把每拍当独立样本更合理，但重复球员、共同比赛、同一机位的依赖仍存在，少量比赛的结果也不稳定。汇总热力图又使用逐拍中位数，拍数较多的一场能影响个人典型值。应报告每人每场样本与保留率，增加以球员/比赛分组的区间估计或层级模型，并区分描述性差异与统计结论。

9. **10% 相机阈值有人工例外。** 原文和 `CAMERA_OK` 都允许若干相机解释量超过 10% 的指标进入热力图，包括站姿角及部分转体指标。这不是代码隐瞒的漏洞，但复刻不能笼统宣传“全部指标都不受相机影响”；例外、影响比例和手机可比性应逐行进入数据和模型提示词。

10. **平均骨架与典型视频不是同一个对象。** 平均骨架是髋中心、躯干尺度和触球时间对齐后逐点平均；没有非线性时间扭曲，不同人自然阶段时刻可不同。典型视频是特征距离接近中位数的一次真实击球。两者不必逐帧重合，平均姿态也未必对应某次物理可实现的动作；不应要求模型把两者当同一条证据重复计数。

### C. 评估、数据可得性与 LLM 的问题

11. **原文组件成绩不能替代整条链的误差。** 原文人框评测是 197 张转播帧；骨架表用近距离 Tennis Player Actions 图像的 OKS 和 COCO-WholeBody 的脚部标注；球场/球的评测各为 100 帧。原文自己说明这些集合更适合排序模型，未直接衡量其在目标录像上的准确性。L4/L40S 的速度也不能直接当 RTX 5090 实测速度。需在目标视频上核验触球时刻、身份、关键点、球场映射和最终特征，而不仅检查程序是否运行成功。

12. **公开短片不等于完整原始研究数据。** 网站片段带裁剪、骨架和文字覆盖，很多是同一次击球的多个导出版本；不能把每个文件当独立样本重新建立职业分布。完整私人手机原片不在仓库中，官方 YouTube 转播也可能有下载/可用性限制。若仅从公开页面提取中位数或骨架，应明确标为“已发表数据重分析”，不能称从原始录像重算全部特征。

13. **历史教练对话不能精确重放。** 原文记录先看数据、后看片段修订，但仓库没有其完整逐轮对话与全部原始附件；页面内模型名仅是作者对历史运行的描述。`others_tab.coach` 则是另一条可复现调用，实际图片列表为空，只发送汇总测量文本。提示词中“看完比赛后”的角色描述不代表模型真的收到连续录像。新运行应存完整请求、数据来源、图片列表、模型 ID、推理设置、输出 schema 和结果，不应把文字相似程度当作正确性。

14. **仅换模型名称不构成复刻。** 用 Codex 重生成建议，应固定同一版测量、同一有效指标集、同一专业基准和相同录像窗口，记录哪些判断有量化依据、哪些来自画面、哪些因证据不足保留；避免直接要求模仿历史 Claude 的结论。程序成功返回 schema 合法 JSON 只说明接口和结构通过，不说明技术建议正确。
